# 🤖 LeRobot 统一控制界面 - 快速开始

## 简介

一个基于 Gradio 的 Web UI，把机器人推理工作流（部署、回放、相机预览）
整合到一个友好的 yaml 编辑器 + 启动器。

**核心思路**：**YAML 是真相源**。UI 只是 `deploy_config*.yaml` /
`replay_config.yaml` 的友好编辑界面——表单只是结构化视图，
可以直接在 YAML Tab 里改文本。启动时 UI 把当前 YAML 写到
`tempfile/robot_config_*.yaml`，并以 `--config <tmp>` 调用对应脚本。

## 特性

- **🚀 模型部署**: 部署 ACT、SmolVLA 或任何训练好的策略到真实机器人
- **🔄 数据集回放**: 回放 HuggingFace 数据集中的示教轨迹
- **📹 相机预览**: 实时相机画面可视化
- **🧪 数据处理**: 一键触发 5 种数据处理工具 (sanity / clean / merge / 时间戳对齐 / v2 schema 转换)
- **🏋️ 模型训练**: 在 UI 启动 ACT / SmolVLA / ACT fine-tune 训练 (5 阶段: env / check / smoke / train / eval)
- **📄 YAML 编辑**: 直接编辑 yaml，与现有 `deploy_config*.yaml` 格式完全兼容
- **📝 表单视图**: YAML 的可选结构化视图（滑块/输入框/复选框）
- **🔄 双向同步**: 表单 → YAML / YAML → 表单
- **💾 模板加载**: 一键加载现有 yaml 模板（`deploy_config_chunk` 等）
- **📊 实时日志**: 实时监控进程输出

## 安装

```bash
# 使用 uv（推荐）
uv sync --extra ui

# 或使用 pip
pip install "gradio>=4.0.0,<6.0.0" "pyyaml>=6.0.0,<8.0.0"
```

## 快速启动

```bash
# 从仓库根目录
python workflows/robot_interaction/ui/launch.py

# 或使用 Python 模块语法
python -m workflows.robot_interaction.ui.launch
```

界面将在 **http://localhost:7860** 可用。

## 工作流

### 基本流程

1. **加载模板**：顶部"加载模板配置"下拉菜单选择一个 yaml（如 `deploy_config_chunk`）
2. **编辑配置**：两种方式任选
   - **YAML Tab**：直接编辑文本（power user 友好）
   - **表单 Tab**：通过滑块/输入框/复选框编辑，然后点"🔄 从表单刷新 → YAML"
3. **启动**：点 🚀 启动，UI 把当前 YAML 写到 tempfile 并以 `--config` 调用脚本

### 部署 ACT 策略（推荐用 YAML 编辑）

1. 顶部"加载模板"选 `deploy_config_chunk`
2. Tab "YAML"：把 `policy.path` 改成你的模型路径
3. Tab "YAML"：把 `dataset.repo_id` 改成你的 repo_id
4. 点 🚀 启动

### 部署 SmolVLA 策略

1. 顶部"加载模板"选 `deploy_config_chunk` 或 `deploy_smolvla_default`（如有）
2. Tab "YAML"：
   - `policy.path` → SmolVLA 模型路径
   - `dataset.single_task` → 任务描述（如"拿起红色方块放到蓝色碗里"）
   - `inference.rename_map` → 相机重命名（如 `camera1: image`）
3. 点 🚀 启动

### 回放数据集轨迹

1. 顶部"加载模板"选 `replay_config`
2. Tab "YAML"：改 `dataset.repo_id` / `dataset.episode` 等
3. 点 🚀 启动

### 预览相机画面

1. 切到"相机预览"模式
2. Tab "表单"：在"相机设置"选要显示的相机、FPS、窗口大小
3. 点"🔄 从表单刷新 → YAML"
4. 点 🚀 启动（`show_cameras.py` 会自动从 `--config` 读 robot/policy，从 CLI 读相机运行参数）

### 🧪 数据处理模式

切到"数据处理"模式后在"操作"下拉选择 5 种之一：

- **数据集烟测**: 跑 `sanity_check.py`，检查目录结构 / `info.json` 字段 / LeRobotDataset 可加载性 + ACTPolicy forward shape。
- **清洗脏 Episode**: 跑 `clean_dirty_episodes.py`。**默认 dry-run**，确认无问题后再取消勾选 `Dry-run`。输入路径与输出路径不能相同。
- **合并数据集**: 跑 `merge_two_datasets.py`。"源数据集路径"每行一个，至少 2 个；输出目录**不能已存在**。
- **时间戳对齐检查**: 跑 `check_timestamp_alignment.py`。退出码 1 = 发现 drift（业务结果，不是错误）。
- **v2 Schema 转换**: 跑 `v2_convert.py`。勾选相机复选框决定保留哪些相机；输出目录已存在则拒绝覆盖。

### 🏋️ 模型训练模式

切到"模型训练"模式后选择脚本和阶段：

| 脚本 | 说明 |
|---|---|
| ACT | 调 `train_act.sh` 训练 ACT |
| SmolVLA | 调 `train_smolvla.sh`，需要 SmolVLA 专属参数 (chunk_size, policy_lr 等) |
| ACT Fine-tune | 调 `finetune_act.sh`，需要 PRETRAINED_CKPT + NEW_DATASET |

| 阶段 | 说明 |
|---|---|
| `env` | 只检查环境（GPU/依赖），不启动训练 |
| `check` | 只校验数据集（4 条规则），不启动 |
| `smoke` | 50 步烟测，建议第一次跑 |
| `train` | 正式训练（默认 400k 步） |
| `all` | env + check + smoke + train + eval |
| `eval` | 仅打印评估命令 |

> ⚠️ **注意**: 训练通过 `bash` 子进程启动，环境变量走白名单（不会污染 Gradio 主进程）。所有训练日志输出到 `outputs/deploy_logs/model_training_<script>_<phase>_<ts>.log`。点停止会 `killpg` 终止整个训练进程组（含 `lerobot-train` 后代）。

> ⚠️ **fine-tune 注意点**: `finetune_act.sh` 没有像 ACT/SmolVLA 那样的 phase dispatch，总是跑完整训练流水线。其它脚本的 `eval` 阶段只是打印命令，不会评估模型。

## 可用模板

`workflows/robot_interaction/` 下的所有 `.yaml` 文件都会出现在"加载模板配置"下拉里：

- `deploy_config` — 同步模式部署（HTTP-only）
- `deploy_config_chunk` — 开环 chunk 模式部署（当前默认）
- `deploy_config_hybrid` — Hybrid 部署（HTTP 观测 + SDK 动作）
- `replay_config` — 回放

> 加新的 yaml 文件后点 🔄 刷新下拉菜单即可。

## 保存自定义配置

1. 在 Tab "YAML" 编辑好内容
2. 顶部输入新模板名称（如 `my_chunk_config`）
3. 点 💾 保存为模板 → 写到 `workflows/robot_interaction/my_chunk_config.yaml`
4. 下次重启 UI 后会出现在下拉菜单里

## 配置文件结构（YAML schema）

UI 写入和读取的 yaml 格式与 `deploy.py` / `replay.py` / `show_cameras.py`
直接吃的格式一致。详细字段说明见各 yaml 文件顶部的注释。

```yaml
mode: deploy  # deploy | replay | camera_preview（UI 用来识别模式；脚本本身不读）
policy:
  path: ...
  device: cuda
robot:
  http_base_url: ...
  ...
inference:
  type: sync | rtc | chunk
  ...
dataset:
  repo_id: ...
  ...
```

部署 / 回放的 yaml 字段位置略有差异：

- **deploy**: `inference.return_to_initial_position` 在 `inference.*`
- **replay**: `play_sounds` 和 `return_to_initial_position` 在 yaml 根

UI 的 `save_yaml` / `load_yaml` 自动做 mode-aware 转换，无需手动调整。

## 推理类型说明

- **sync**: 同步模式 — 推理完整 chunk，执行所有动作后再重新推理（稳定，响应较慢）
- **rtc**: Real-Time Chunking（实时分块）— 执行前 N 步的同时推理下一个 chunk（响应更快）
- **chunk**: 开环分段下发 — 每 `chunk_interval_s` 推理一次，把前 `n_action_steps` 个动作一次性 POST 给机器人（最稳；当前默认部署模式）

## VLA 任务描述

视觉-语言-动作模型需要任务描述：

```yaml
dataset:
  single_task: "拿起红色方块放到蓝色碗里"
```

任务描述会被 tokenize 并在推理时作为条件输入策略。

## 常见问题

**Q: UI 无法启动？**
A: 检查依赖安装：`pip list | grep gradio`，重新安装：`pip install --upgrade "gradio>=4.0.0"`

**Q: 进程启动失败？**
A:
1. 查看 **进程日志** 面板
2. 验证机器人 HTTP 端点可访问：`curl http://192.168.10.123:8010/state`
3. 确保模型路径存在且包含 `config.json`

**Q: VLA 模型提示需要任务描述？**
A: 在 Tab "YAML" 加 `dataset.single_task: "..."`，或在 Tab "表单"的
"数据集设置（部署）"里填任务描述，然后点"🔄 从表单刷新 → YAML"。

**Q: 如何从另一台电脑访问 UI？**
A: UI 默认监听 `0.0.0.0`，可通过 `http://<机器人电脑IP>:7860` 访问。

**Q: 表单和 YAML 不一致？**
A: 点 Tab "YAML" 里的"📋 YAML → 应用到表单"用 YAML 内容覆盖表单，
或点"🔄 从表单刷新 → YAML"用表单覆盖 YAML。

### 关键安全约束

- **白名单**: UI 不会注入任意命令或任意环境变量。脚本路径固定；训练 env 只注入 21 个已批准的 key。
- **资源隔离**: Bash 训练通过 `os.setsid()` 自建进程组，stop 用 `killpg` 杀整个组。
- **dry-run 默认开**: 清洗 / 合并 / v2 转换默认 `dry_run=true`，避免误写。
- **YAML schema 不变**: 旧 `deploy_config*.yaml` / `replay_config.yaml` 继续按原版兼容加载（带 warning 的容错过滤）。
